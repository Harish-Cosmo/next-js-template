# Design system

The system is small on purpose: a token file, a Tailwind mapping, a handful of primitives and a set of rules. If a screen needs something the system lacks, add a token or a primitive in the same change and say why.

## Tokens

All tokens live in `app/theme.generated.css`, generated by `npm run setup`. They are HSL triplets without the `hsl()` wrapper, so Tailwind can apply opacity:

```css
--foreground: 0 0% 0%;
/* used as hsl(var(--foreground) / 0.72) */
```

| Group | Tokens |
| --- | --- |
| Surface | `--background`, `--foreground`, `--card`, `--popover` |
| Action | `--primary`, `--secondary`, `--accent`, `--destructive`, each with a `-foreground` |
| Support | `--muted`, `--border`, `--input`, `--ring` |
| Shape | `--radius` |
| Type | `--font-sans`, `--font-mono` |
| Brand | `--brand-50` through `--brand-900`, derived from the accent colour |
| Motion | `--ease-out-expo` |

`tailwind.config.ts` maps these to utility names (`bg-background`, `text-foreground`, `border-border`, `rounded-lg`, `font-sans`, `text-brand-600`). Components use the utilities, never the raw variables, except in `globals.css`.

## Colour

- **Primary** is the main action colour. It is the button background, not a decoration.
- **Accent** is for links, focus rings and emphasis. The brand scale is generated from it, so `brand-600` is a readable link colour on white.
- **Neutrals** are the foreground at reduced opacity, not a separate grey palette. This keeps light and dark mode consistent.
- Never use a colour to carry meaning alone. Pair it with text or an icon.

### Text tiers

Three tiers, and nothing else:

| Class | Use |
| --- | --- |
| `text-foreground` | Headings and primary text |
| `text-body` | Paragraphs and descriptions |
| `text-subtle` | Labels, captions, fine print |

Inside `.on-dark`, both tiers invert to white automatically. Put `.on-dark` on a dark section and use the same classes.

## Type

Fluid sizes scale with the container, not the viewport, so a component in a narrow column types correctly:

| Class | Role |
| --- | --- |
| `text-hero` | The one line a visitor reads first |
| `text-display` | Page title on an interior page |
| `text-h1` | Section heading |
| `text-h2` | Card or sub-section heading |
| default body | Paragraphs; pair with `text-body` for colour |

The fluid utilities use `cqi` units and need a `container-type: inline-size` ancestor. `app/layout.tsx` sets it on the root wrapper. Do not remove it.

Body copy is set on `body` from `--font-sans`. Code uses `--font-mono` through the `font-mono` utility or `.prose-content code`.

## Space and layout

- `Container` sets the horizontal rhythm: `max-w-6xl` plus `.page-pad`.
- `.section-pad` sets vertical rhythm. Use it on every full-width band so sections breathe equally.
- `Section` is a band; `SectionContainer` is a band that owns its container.
- Prefer a 4px-based scale from Tailwind (`gap-2`, `p-4`, `mt-8`). Avoid arbitrary values unless matching an optical detail.

## Surfaces

| Class | Use |
| --- | --- |
| `.surface` | A resting panel: hairline border, soft shadow |
| `.surface-sm` | The smaller radius for nested panels |
| `.surface-flat` | A panel with no shadow |
| `.surface-lift` | The one elevated state, for a hovered or featured card |
| `.surface-interactive` | Adds the hover transition to a `.surface` |
| `.solid` | A filled block in the primary colour |

One elevation. A card that is not interactive does not lift.

## Components

| Component | Contract |
| --- | --- |
| `Button` | Variants: `default`, `outline`, `ghost`, `link`, `destructive`. Sizes: `sm`, `default`, `lg`, `icon`. `asChild` renders a link with button styles. |
| `Container` | Horizontal rhythm. Change the max width here once. |
| `Section` / `SectionContainer` | Vertical rhythm. |
| `SectionHeader` | Eyebrow, title and optional description as one block. |

A new primitive belongs in `components/ui/` only when it is reused or when it encodes a rule. A one-off layout is a `div` with utilities.

## Motion

- Use `--ease-out-expo` for anything that moves.
- Motion explains a state change; it does not decorate an entrance.
- Hover and press transitions stay at 150–200ms.
- `prefers-reduced-motion` disables transitions and smooth scroll globally in `globals.css`. Never override that.

## Accessibility

- Every interactive element is reachable by keyboard and has a visible focus ring. The global `:focus-visible` rule provides it; do not remove it.
- A control that is not a link is a `<button>`. A navigation is a `<nav>` with an `aria-label`.
- Images that carry meaning have `alt`; decorative images have `alt=""`.
- Text contrast: body at 72% and subtle at 58% of the foreground both pass on white. Do not go lighter for body copy.
- The skip link is the first focusable element. Keep it.
- Test at 320px wide. Nothing scrolls horizontally except a code block or a table, and those scroll inside their own box.

## Reviewing a screen

Before shipping, check:

- [ ] No hardcoded hex, `text-[13px]` or arbitrary spacing that a token covers.
- [ ] One `text-hero` per page, and the heading order does not skip a level.
- [ ] Body copy uses `text-body`; captions use `text-subtle`.
- [ ] One elevation; interactive cards use `.surface-interactive`.
- [ ] Focus visible on every control; the skip link works.
- [ ] 320px wide, 200% zoom, and `prefers-reduced-motion` all hold up.
